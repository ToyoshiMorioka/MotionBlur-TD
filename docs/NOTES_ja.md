# 開発メモ：わかったこと

作りながら TouchDesigner 2025.33230（macOS）で確かめたことの記録（2026-11-25）。数字は手元の Mac・1280×720 で測ったもの。

## 形の動きの取り方

- **POP の点に前のフレームの位置を持たせるには、Feedback POP が使える。** Target POP に自分の入力の元を指定すると、1 フレーム前のその POP が出てくる。GLSL POP で、入力 0（今）と入力 1（前）の点の位置を同じ番号で読み、PrevP という属性にする。点の数が違う時は PrevP = P にする
- **GLSL MAT で POP の属性を読むには、Attributes ページで宣言して `TDAttrib_名前()` で読む**（例：`TDAttrib_PrevP()`）
- **Object CHOP（Compute = Mat）の行列で Transform POP を動かすと、止まっている形でも毎フレーム計算し直しになる。** Object CHOP が毎フレーム計算されるため。最初はこの形（VoxelConeTracing-TD の slotN と同じ）で、形 10 個で 1.4 ms かかり、VCT と合わせて 60 → 52 fps に落ちた。形の世界での置き方は、材質のシェーダに行列で渡す形に変えた（Python で毎フレーム worldTransform を読んで入れる）
- **Feedback POP は毎フレーム計算される。** 点が動いている形にだけつなぎ、30 フレーム止まっていたら外すようにした（動いているかは、元の POP・SOP の totalCooks が増えたかで見る）。止まっている形では、点の計算がまったく走らない
- **動きは、今と前のフレームの両方を同じ求め方の行列で画面に写して差を取る。** 今の位置は TD の `TDWorldToProj` でも出せるが、前の位置は Python の `cam.projection(w, h) × ビュー` で求めるので、今の位置も同じ求め方にそろえた（求め方が違うと、止まっている物にも動きが出るおそれがある）

## ぼかし

- **タイルごとの最大を 1 回で K×K 画素読むと遅い**（K = 24 で 1.3 ms）。出力の画素が少なく、並列に動けないため。横と縦の 2 回に分けて 0.15 ms になった
- **Shutter 0.5（1 フレームの半分の時間）だと、ぼけは思ったより小さい。** 1 フレームに 15 画素動く縁で、ぼかしの半径は約 4 画素。60 fps の映像では、これが実際のカメラ（180° シャッター）に近い。見本では効果が見えやすいよう 1.0 にした
- **ぼかす前と後を比べる時、保存の直前に計算を強制すると、絵と動きのバッファが別のフレームの物になり、片側だけぼけた絵になった。** ふだん動かしている時には起きない（同じフレームの絵と動きで計算される）。比べる時は、タイムラインを止めてから保存する

## 組み合わせ

- MotionBlur は、ぼかす絵を描いた Render TOP からカメラ・解像度・形の一覧を取るだけなので、材質を選ばない。VoxelConeTracing-TD の見本では、ガラスを重ねた絵とトーンマップの間に入れ、Render に `render_opaque`、Geometry に `geo_* glass_*` を指定した。VCT 側のファイルは何も変えていない
- VCT と合わせた時の速さ：60 fps → 59 fps（MotionBlur の GPU 時間は 1 ms 弱）
